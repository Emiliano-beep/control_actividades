1. Flujo colaborativo
Supón que quieres colaborar con el repositorio de otro desarrollador. Ordena y explica los siguientes elementos:
Push, Fork, Pull Request, Clone, Merge, Commit, Review, Branch y Modificar archivos. Agrega cualquier
operación que consideres necesaria.

R= Primero es un Fork para duplicar en repositorio en github, despues un clone para duplicarlo en tu PC, depues un branch para crear la rama donde trabajaras, despues de que hallas creado o modificado archivos es un stage o git add ., despues haces un commit, donde especifiques tus cambios, despues un push para tu repositorio, luego envias un pull Requests, despues el propietario revisara tus cambios con un review, despues hara un merge para sincronizar los datos.


2. Fork y Clone
Analiza la afirmación: “Clone crea una copia del proyecto dentro de mi cuenta de GitHub”. Indica si es correcta
y explica la diferencia entre Fork y Clone.

R = No es correcta, Clone clona un repositorio pero dentro de vsc no de github, para clonar el repositorio en gitgub es un fork.

3. Pull Request
Supón que realizaste Fork, Clone, Branch, Modificar, Commit y Push. Responde: ¿los cambios ya forman parte
del repositorio original? ¿Qué debe ocurrir para incorporarlos?

R = Aun no forman parte del repositorio original necesitas hacer un push request para solicitar la revision de tus cambios, y el propietario debe aceptarlos.

4. Request Changes
El propietario revisa tu Pull Request y selecciona Request Changes. Explica qué debes hacer, si necesitas crear
otro Pull Request y qué ocurre cuando realizas nuevamente push.

R = Debo checar en que estoy mal o que hize mal para cambiarlo y volver hacer un push y despues un push request.

5. Merge y repositorio local
Un Pull Request fue aceptado y se realizó Merge en GitHub. Sin embargo, el repositorio local del propietario no
contiene los cambios. Explica por qué sucede y qué operación debe realizarse.

R = Necesita hacer un git pull  para que carge el repositorio local.

6. Sync Fork
Tu Fork fue creado varios días atrás y el repositorio original recibió nuevos commits. Explica qué herramienta
utilizarías, qué repositorio se actualiza y qué diferencia existe entre Sync Fork y git pull.

R = Utilizaria un Sync fork para que mi repositorio se actualize, Sync fork sirve para actualizar de nuevo el fork y que se actualizen los cambios y el git pull  es para que cargue los datos en vsc.
